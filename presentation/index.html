What is OpenSKIZZE?

An interactive decision-support tool for early-stage climate-aware urban design

OpenSKIZZE helps you systematically explore diverse building arrangements for a site while considering climate performance (wind flow, ventilation).

Instead of manually testing a few design options, the system automatically generates 1,000–100,000 diverse alternatives and helps you understand the trade-offs between different morphological choices.

The Problem We Solve

The "Praxis Gap"

  • Regional climate models (like KLAM_21) provide valuable insights but operate at 100m resolution—too coarse for building-scale decisions
  • Detailed CFD simulations are accurate but take hours per design—impractical for early-stage exploration
  • Manual iteration is slow, unsystematic, and prone to bias toward familiar solutions
Result: Planners lack tools to quickly explore climate-adaptive massing options during the critical early design phase.

How OpenSKIZZE Works

6-Step Workflow (Complete in ~30 minutes)

Step What You Do What the System Does
1. Scope Select parcel on map, set wind direction Loads existing buildings from LOD2 data
2. Constraints Define height limits, spacing, target metrics (GRZ, GFZ) Configures optimization parameters
3. Optimize Click "Start" Generates 1,000–100,000 diverse designs (3–8 min)
4. Analysis Explore archive heatmaps, cluster results Identifies design archetypes automatically
5. Compare Select designs side-by-side Synchronized 3D views for comparison
6. Export Download report PDF with archetypes, trade-offs, recommendations

Key Features for Planners

🎯 Diversity, Not Just "The Best"
Traditional optimization finds one "optimal" solution. OpenSKIZZE finds the best solution for every combination of features—high density vs. low density, tall vs. compact. You see the full range of what's possible.

📊 Automatic Archetype Discovery
The system uses advanced clustering (HDBSCAN, K-Medoids, Hierarchical) and similarity metrics (SSIM, t-SNE) to identify distinct design families. Consensus maps show placement patterns that appear across multiple high-performing solutions.

🏗️ Real Data Integration
LOD2 CityGML (NRW data), ALKIS Parcels, Physical Units (meters, m²).

⚖️ Regulatory Metrics Built-In
GRZ (Grundflächenzahl), GFZ (Geschossflächenzahl) - Direct comparison to BauNVO requirements.

System Architecture, Algorithms, and Validation

System Overview

OpenSKIZZE: Open-source QD-based decision-support system for climate-aware urban massing exploration

  • Core Algorithm: MAP-Elites via PyRibs 0.6.1
  • Interface: Dash 2.17 + Dash Bootstrap Components (web-based)
  • Backend: Python 3.12, NumPy, GeoPandas, Numba JIT
  • Data Sources: NRW LOD2 CityGML, ALKIS WFS

Quality-Diversity Optimization

Why QD Instead of Single-Objective?

Approach Output Limitation
Single-objective One "optimal" solution Ignores alternative trade-offs
Multi-objective (Pareto) Pareto front High-dimensional fronts hard to navigate
Quality-Diversity Best solution per behavioral niche Full solution space illumination
MAP-Elites Implementation:
GridArchive: 5^d niches (d = 3-8 features)
Emitters: 5-10 GaussianEmitters (σ = 0.05-0.2)
Batch: 16-64 solutions per generation
Generations: 1000-100,000

Parametric Encoding

Genome Structure

  • Fixed dimension: 60 genes
  • 10 buildings × 6 genes each: [width, length, height, x, y, active]
  • Gene sampling: Normal distribution → CDF transform to [0,1]

Phenotype Expression

Genome (60 floats) → 2D Heightmap (meters)

  • Grid: 3m × 3m pixels
  • Heights: floors × 3m/floor
  • Buildable mask: parcel boundary enforcement
  • JIT-optimized: 165× speedup via Numba

Evaluation Pipeline

Climate Objectives

1. Street Canyon (geometric, dense contexts, ~0.8ms)
Components: Ground-level corridors (35%), Lateral ventilation (25%), Height variation (15%), Partial penetration (25%).

2. GP-KLAM (validated physics, <10ms)
Model: Gaussian Process regression. Training: 5,000+ KLAM_21 simulations. Output: Mean airflow velocity, variance. Accuracy: R² > 0.85.

Performance Optimizations

Component Baseline Optimized Speedup
Phenotype expression 82.5ms 0.5ms 165×
Street canyon 22.4ms 0.8ms 28×
Key Techniques:
  • Numba JIT Compilation: Replaces scipy.ndimage.rotate
  • Label Caching: Reuse scipy.ndimage.label results
  • Single-Threaded for Small Batches: Avoids MP overhead for batch < 100

Combined Effect: 724s → 26s for 50K evaluations (27× speedup)

QD Hyperparameter Benchmark

Findings from 54 runs (18 configs × 3 parcel sizes):

  • More emitters (7-10): +15-20% QD-score
  • Higher σ (0.15): More diversity, slower convergence
  • Larger batch (32-64): Reduces MP overhead
  • Parcel size invariant: Same hyperparameters work across scales

Production recommendation: 7 emitters, σ=0.1, lr=0.01, batch=32

Cold Air Flow Optimization

KLAM-21, Surrogate Models, and Flux Objectives

KLAM-21 Configuration

KLAM_21 (KaltLuftAbflussModell) simulates nocturnal katabatic flows.

  • Grid: 3m × 3m cells
  • Terrain: 1° slope upwind (cold air source)
  • Wind: 5 m/s from west (270°)
  • Duration: 4 hours

Output Variables: Velocity ($u, v$), Cold air layer height ($H_x$), Cold air content ($E_x$)

Cold Air Flux Objective (Φ)

Maximize cold air ventilation through the urban parcel.

$$\Phi = \bar{E}_x \times \bar{u}_{2m}$$
  • $\bar{E}_x$ = Mean cold air content (cooling potential)
  • $\bar{u}_{2m}$ = Mean wind speed at pedestrian level (transport)
  • Units: 100 W/m² (energy flux)

Why? Combines cooling capacity with transport efficiency. Higher correlation with both wind and thermal content than either alone.

SAIL for Sample Generation

KISS-GP Surrogate Model

Kernel Interpolation for Scalable Structured Gaussian Processes

  • Input: 62 dimensions (60 genome + width + height)
  • Kernel: Matérn 2.5 with ARD (Automatic Relevance Determination)
  • Approximation: Grid Interpolation for O(n) scaling
  • Training Data: ~97,500 samples across 15 parcel sizes
Performance Targets:
R² > 0.90 | RMSE < 0.5 m/s | Prediction time < 5 ms

Pipeline Summary

  1. Parcel Analysis: Identify 15 representative sizes
  2. SAIL Training: Generate 5000 elites + 1500 random per size (HPC)
  3. KISS-GP Training: Train 62-dim GP on combined dataset
  4. Validation: Test interpolation on unseen sizes
  5. Deployment: Replace KLAM-21 (5-10 min) with GP (~2 ms) in OpenSKIZZE
